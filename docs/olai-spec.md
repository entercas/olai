# Olai — build spec for Claude Code

Olai (ஓலை, "palm leaf") is a personal note-taking app for macOS and iPhone. This file is the full specification. It lives in the repo at `docs/olai-spec.md` and is referenced from prompts; it does not replace `CLAUDE.md`.

## How to use this file with Claude Code

Work in **Claude Code Desktop** (Code tab, macOS) so the iOS Simulator pane is available. Xcode must be installed but is never opened after the one-time sign-in below; all builds run headless via `xcodebuild`.

One phase per session. Suggested prompts:

- Bootstrap + Phase 1:
  `Read docs/olai-spec.md fully. Set up the project as described in "Project bootstrap" without me opening Xcode, confirm xcodebuild builds clean for macOS and iOS Simulator, then implement Phase 1 only and run it in the iOS Simulator. Do not start Phase 2. When done, tell me how to verify the Phase 1 done criteria on real devices.`
- Later phases:
  `Read docs/olai-spec.md. Phases 1–N are complete and committed. Implement Phase N+1 only. Do not change the "Non-negotiable decisions"; if you think one is wrong, stop and explain instead.`
- Fixes:
  `Read docs/olai-spec.md. In Phase N, <describe the bug>. Fix it without touching other phases.`

Verify each phase's done criteria yourself, then commit.

## Prerequisites (one time, by hand)

1. Install Xcode 16+ from the App Store, including the iOS platform when prompted. Open it once, sign in with your Apple ID under Settings → Accounts, then quit it.
2. Install Claude Code Desktop (macOS), Node 20+, Python 3.11+, and `xcodegen` (`brew install xcodegen`).
3. Find your Apple Team ID at developer.apple.com → Membership; Claude Code will ask for it.
4. If `xcodebuild -allowProvisioningUpdates` fails to register the iCloud container automatically, create `iCloud.com.entercas.olai` once at developer.apple.com → Certificates, Identifiers & Profiles → Identifiers → iCloud Containers, and re-run the build.
5. Free developer accounts work for development; a paid account is needed for TestFlight and for builds that stay on the iPhone beyond 7 days.

## Project bootstrap (Claude Code does this)

- `git init` if not already; add this file under `docs/`.
- Generate `Olai.xcodeproj` from `project.yml` with **xcodegen**. Product name `Olai`, bundle ID `com.entercas.olai`, one multiplatform SwiftUI app target (or two targets, macOS and iOS, sharing sources), deployment targets macOS 15 / iOS 18, Swift 6, automatic signing with the provided Team ID.
- Entitlements per platform: `com.apple.developer.icloud-services = [CloudKit]`, `com.apple.developer.icloud-container-identifiers = [iCloud.com.entercas.olai]`, `aps-environment = development`. Info.plist `UIBackgroundModes = [remote-notification]` on iOS.
- Verify: `xcodebuild -scheme Olai -destination 'platform=macOS' build` and `xcodebuild -scheme Olai -destination 'platform=iOS Simulator,name=iPhone 16' build` succeed.
- Device install for sync testing: `xcrun devicectl device install app` to the plugged-in iPhone.
- Never open Xcode GUI; never edit `CLAUDE.md`.

## Product summary

Single-user rich-text notes with folders and sub-folders, templates, iCloud sync, a read-only Markdown export ("mirror"), and a small MCP server so an agent can produce weekly summaries, next-week priorities, and a running achievements-vs-goals view for performance reviews.

## Non-negotiable decisions

1. **Block-document model.** A page's body is a JSON document (TipTap/ProseMirror schema). Never store rich text as RTF, HTML, or NSAttributedString archives.
2. **Web editor in a WKWebView.** TipTap runs inside `WKWebView` on both platforms. Swift owns storage, sync, navigation, templates, calendar, voice, and export. Do not build a TextKit editor.
3. **SwiftData + CloudKit private database** for sync. No custom backend.
4. **Markdown mirror is export-only in v1.** Nothing reads the mirror folder back into the app.
5. **Native Swift/SwiftUI**, one Xcode project generated by xcodegen, targets macOS 15+ and iOS 18+. Shared code in a Swift package `OlaiCore`.

## Data model (SwiftData, CloudKit-compatible)

CloudKit rules: every stored property has a default or is optional; every relationship is optional; no `@Attribute(.unique)`.

```swift
@Model final class Folder {
    var id: UUID = UUID()
    var name: String = ""
    var sortOrder: Int = 0
    var isArchived: Bool = false
    var createdAt: Date = Date()
    var parent: Folder?
    @Relationship(deleteRule: .cascade, inverse: \Folder.parent) var children: [Folder]?
    @Relationship(deleteRule: .cascade, inverse: \Page.folder) var pages: [Page]?
}

@Model final class Page {
    var id: UUID = UUID()
    var title: String = ""
    var templateID: String?          // "weekly", "ai-prompt", "interview", "transcript", "goals"
    var body: Data?                  // TipTap JSON, UTF-8
    var plainText: String = ""       // derived, for search
    var isArchived: Bool = false
    var isPinned: Bool = false
    var createdAt: Date = Date()
    var updatedAt: Date = Date()
    var periodStart: Date?           // weekly pages: Monday of the week
    var eventDate: Date?             // transcript pages: meeting date/time
    var goalIDs: [String] = []       // links to Goal pages (Page.id as string)
    var folder: Folder?
    @Relationship(deleteRule: .cascade, inverse: \Attachment.page) var attachments: [Attachment]?
}

@Model final class Attachment {
    var id: UUID = UUID()
    var filename: String = ""
    var mimeType: String = ""
    @Attribute(.externalStorage) var data: Data?
    var createdAt: Date = Date()
    var page: Page?
}
```

Container: `ModelConfiguration(cloudKitDatabase: .private("iCloud.com.entercas.olai"))`. Autosave on; the editor bridge debounces saves (500 ms after the last change).

## Editor (web) and Swift bridge

- TipTap extensions: StarterKit, TaskList/TaskItem, Highlight, Image, Link, Underline, Placeholder. Table is a later addition.
- Built with Vite into a single `editor.html` with inlined JS/CSS; copied to `Olai/Resources/editor.html` and loaded via `loadFileURL`.
- Images in the doc are `image` nodes whose `src` is `attachment://<uuid>`. A `WKURLSchemeHandler` for `attachment://` serves bytes from the `Attachment` record.
- Bridge (`WKScriptMessageHandler`, handler name `bridge`), JSON messages:
  - Swift → JS: `setDocument({json, readOnly})`, `insertImage({id})`, `insertText({text})`, `applyTheme({dark})`
  - JS → Swift: `ready`, `documentChanged({json, plainText})`, `requestImagePaste({base64, mime})`, `slashCommand({name, payload})`
- Slash commands handled in Swift: `/event`, `/task`, `/date`, `/template`.
- Editor respects system light/dark appearance and never causes the outer SwiftUI view to scroll.
- Toolbar (SwiftUI, above the web view): bold, italic, underline, highlight, H1/H2/H3, bullet list, numbered list, task list, indent, outdent, image, mic, mind map toggle.

## Sidebar and navigation

`NavigationSplitView`: sidebar is folders → subfolders → pages as a recursive `OutlineGroup`; expand/collapse state persisted per folder in `@AppStorage`. Detail is the editor. On iPhone it collapses to a stack. Bottom of the sidebar has an "Archive" section listing archived folders and pages. Context menu on items: rename, move to folder, archive/unarchive, delete, new page from template. `.searchable` over `Page.title` and `Page.plainText`. Pinned pages sort first within a folder.

## Templates

Templates are JSON files in `Resources/Templates/`, each:

```json
{ "id": "weekly", "name": "Weekly page", "kind": "page", "titlePattern": "Week of {{weekOf}}", "body": { ...TipTap JSON... } }
```

`kind` is `page` or `folder`; folder templates have `"pages": [ ...page templates... ]`. Title patterns support `{{weekOf}}`, `{{date}}`, `{{time}}`.

v1 templates:
- `weekly` — sections: Priorities, To-do (task list), Actions, Raw notes / conversations, Wins. Sets `periodStart` to the Monday of the current week.
- `ai-prompt` — Prompt, Output, Notes, Tags.
- `interview` — Who / role / company, Context, Questions, Verbatims, Insights, Follow-ups.
- `project` (folder) — creates a folder containing Overview, Decisions, Meeting notes, Open questions.
- `transcript` — Title, Date/time (sets `eventDate`), Participants, Transcript, Summary, Actions.
- `goals` — one page per goal: Goal, Success criteria, Evidence (running bullet list).

## Markdown mirror (export only)

- Mac app only. Root defaults to `~/Olai`; configurable in Settings and stored as a security-scoped bookmark.
- Path: `<root>/<folder path>/<sanitized title>-<8-char id>.md`; archived items go under `<root>/_archive/<folder path>/`.
- YAML frontmatter: `id, title, template, folder, created, updated, period_start, event_date, goals, archived, pinned`.
- Body: TipTap JSON → Markdown via `OlaiCore/MarkdownConverter`. Task items → `- [ ]` / `- [x]`; highlight → `==text==`; headings → `#`; images → `![](attachments/<uuid>.<ext>)` with the file written alongside the page.
- Full export on launch; incremental on every save (debounced 2 s); renames and deletes mirrored. Files in the root that no page maps to are left untouched.
- Never read from this folder.

## MCP server (`mcp-server/`)

Python 3.11+, `mcp` SDK, stdio transport, reads only the mirror folder (path from `OLAI_ROOT` env var, default `~/Olai`). Tools:

- `search_notes(query, folder?, template?, limit?)`
- `get_page(id)`
- `list_pages(template?, folder?, date_from?, date_to?, include_archived=false)`
- `get_weekly_pages(weeks_back)`
- `get_goals_with_evidence()` — goals pages plus every page whose `goals` frontmatter references them
- `append_to_page(id, markdown)` — v1: returns an error stating the mirror is export-only

MCP prompts: `weekly_summary`, `next_week_priorities`, `performance_review_draft(period)`.

Ship `mcp-server/README.md` with config snippets for Claude Desktop and Claude Code, and pytest coverage for every tool using a fixture mirror folder.

## Calendar and tasks

EventKit only. `/event` creates an `EKEvent`; `/task` creates an `EKReminder` with an alarm. The block in the page stores the event/reminder identifier so it can be opened or updated later. Request Calendar/Reminders permission lazily on first use. No custom notification scheduler.

## Voice

- Dictation: WhisperKit on-device (reuse the approach from `entercas/private-notetaker`); streams recognized text into the editor via `insertText`. Mic button in the toolbar on both platforms.
- Transcript import: accept `.vtt`, `.txt`, `.srt`; create a `transcript` page; parse date/time from the filename or VTT header when present; otherwise use file modification date.

## Mind map

Read-only view of the current page's outline (headings + nested bullets) rendered in the same web view with markmap. Toggle from the toolbar. No freeform canvas in v1.

## Build phases and done criteria

1. **Foundation** — bootstrap, models, CloudKit container, sidebar with folders/subfolders/pages, plain `TextEditor` body, rename/move/delete. Run in the iOS Simulator for UI checks.
   Done: builds clean for both platforms; a page created on the Mac appears on the iPhone within a minute on real devices and vice versa; offline edits merge when back online; `CD_Folder`, `CD_Page`, `CD_Attachment` visible in CloudKit Console (Development).
2. **Editor** — TipTap in WKWebView with the bridge; bullets, numbered lists, task lists, headings, highlight, underline, indent/outdent, undo/redo, toolbar.
   Done: document round-trips through JSON with no loss; autosave works; light/dark both correct; editing on one device shows on the other.
3. **Images and paste** — pasteboard and drag-drop on Mac, share sheet and PhotosPicker on iOS, `attachment://` scheme handler, plain-text paste cleanup.
   Done: an image pasted on the Mac renders inline on the iPhone.
4. **Templates and archive** — all six templates, folder template, archive section, search, pin.
   Done: "New weekly page" creates a correctly titled page with `periodStart` set; archived items disappear from the main tree and appear under Archive.
5. **Markdown mirror + MCP** — converter with unit tests, full and incremental export, MCP server with all tools and prompts.
   Done: Claude Desktop, connected to the server, produces a weekly summary from real pages.
6. **Calendar and tasks** — `/event`, `/task`, permissions, open-in-Calendar/Reminders from the block.
7. **Voice** — WhisperKit dictation on both platforms; transcript import.
8. **Mind map** view.

## Conventions

- Swift 6 strict concurrency; model context access from views on `@MainActor`.
- `OlaiCore` has unit tests for the Markdown converter and template loading.
- No third-party Swift dependencies except WhisperKit. Web editor dependencies pinned in `Editor/package.json`; the built `editor.html` is committed so the app builds without Node.
- `project.yml` is the source of truth; regenerate the project with xcodegen after any target/setting change and commit both.
- Commit after each phase's done criteria pass; do not start the next phase with a failing criterion.
- Test CloudKit sync on real devices only; the simulator is unreliable for it.
- Never open Xcode GUI; never modify `CLAUDE.md` or other repo-level settings.
